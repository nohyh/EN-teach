# LUMI 英语学习应用后续开发计划书

> 文档状态：V1.4（阶段 3 执行完成版）
> 适用项目：EN-teach
> 目标：把当前可演示的学生端原型，推进为可持续运营、可发布、可扩展的英语学习产品。

状态标记：✅ 已完成并验证；🟡 已完成基础能力、仍有后续范围；⬜ 尚未开始；🔒 等待生产账号或部署环境。

## 1. 计划摘要

当前项目已具备完整的学生端演示流程、五类课程活动、基础语音与 AI 能力，以及本地进度保存。下一阶段不应继续堆叠孤立页面，而应优先建立真实账号、云端数据、内容生产、学习闭环和运营能力。

推荐的建设顺序如下：

| 优先级 | 建设方向 | 直接价值 |
| --- | --- | --- |
| P0 | 账号、云端数据、数据库迁移、配置与监控 | 让产品从单机演示进入真实多用户环境 |
| P0 | 教材上传、解析、校验、预览和发布 | 建立课程内容持续供给能力 |
| P0 | 错题本、掌握度与间隔复习 | 建立“学—练—错—复习—掌握”的核心闭环 |
| P1 | 积分账本、商城、皮肤与装扮 | 提高持续学习动力，同时保证奖励数据可靠 |
| P1 | 教师后台、班级、作业和数据看板 | 支撑实际教学组织和内容运营 |
| P1 | iOS 适配、真机测试和 TestFlight | 形成可交付的苹果端产品 |
| P2 | 家长报告、通知、离线能力、无障碍 | 提升留存、可达性和家庭使用体验 |
| 持续 | 隐私安全、AI 安全、自动化测试、成本治理 | 保证未成年人产品可长期运营 |

若以 2–3 人小团队推进，建议以约 16 周为首个正式版本周期；每两周形成一个可验收迭代，不将所有功能压到最后统一联调。

## 2. 当前产品基线

### 2.1 已有能力

- Expo + React Native 学生端，Web 使用 Expo DOM 展示高保真界面。
- 真实账号登录、JWT 会话恢复、学生身份、冒险地图、课程、AI 伙伴、作业、错题和成长页面。
- 10 节本地 Mock 课程。
- `word`、`sentence`、`recall`、`pronunciation`、`dialog` 五类课程活动。
- 服务端权威课程进度、学习事件、错题、间隔复习和作业进度；本机缓存继续支持弱网学习。
- FastAPI + PostgreSQL/SQLite + Alembic 后端结构。
- 阿里云 NLS TTS/ASR、SSECP 评分和 DeepSeek 接口骨架。
- NLS Token 自动刷新、结构化请求日志、健康/就绪检查和可选 Sentry。
- 云端语音失败时的本地演示兜底。

### 2.2 当前限制

- 教师、家长和管理员的完整账号流程、关联关系、找回密码尚未实现。
- 已成功提交的课程进度、错题、复习和作业可跨设备恢复；完整离线事件队列和冲突合并仍待 E15。
- 积分、购买、库存、装备、成长统计和徽章已形成后端权威数据；运营可视化配置入口留待阶段 4。
- 课程已有上传、解析、审核、版本和发布流程；生产 OSS/S3 与 OCR 服务仍待接入。
- NLS 自动刷新代码已完成，但正式环境仍需配置最小权限 RAM AccessKey。
- 教师班级看板与家长周报基础版已开始建设；完整家长控制、通知发送和教师批次管理仍待完成。
- iOS 尚未完成设备矩阵验证、隐私声明、TestFlight 和上架准备。
- 缺少生产环境部署、监控、告警、审计、备份和恢复机制。

## 3. 产品原则

1. **学习效果优先于装扮数量**：先完成错题复习与掌握度，再扩充商城内容。
2. **服务端数据为准**：积分、购买、作业、错题和学习记录必须以后端为权威来源。
3. **奖励可追溯**：积分不直接修改余额，所有变化必须进入不可变流水。
4. **内容先校验后发布**：上传教材不能直接进入学生端，必须经过解析、预览、审核和版本发布。
5. **未成年人安全默认开启**：最小化采集数据，AI 输出受控，敏感操作保留审计。
6. **弱网可继续学习**：缓存已发布课程和必要音频，恢复网络后安全同步。
7. **云能力可降级**：语音和 AI 不可用时给出明确提示与可继续路径。

## 4. 核心功能规划

### 4.1 真实账号与多用户体系（P0）

#### 范围

- 用户注册或机构导入、登录、退出、Token 刷新和找回密码。
- 学生、教师、家长、管理员四类角色及权限边界。
- 一个家长可关联多个学生；教师可管理多个班级。
- 学生档案：昵称、头像、年级、课程、时区、学习偏好和吉祥物装扮。
- 多设备登录、会话失效、异常登录记录。
- 本地演示数据迁移到云端账号的单次导入策略。

#### 验收标准

- 两个用户登录同一设备时数据完全隔离。
- 同一用户在 Web 与手机登录后，课程进度、积分、错题和装扮一致。
- 所有受保护 API 均校验身份与角色权限。
- 退出登录后不可读取前一用户缓存中的私人学习数据。

### 4.2 积分系统与皮肤商城（P1）

#### 产品规则

- 积分来源：完成课程、首次满分、按时完成作业、连续签到、错题掌握、阶段挑战。
- 积分消耗：购买 Lumi 皮肤、服饰、背景、徽章或课程主题装饰。
- 首期不开放用户间转账、现金兑换或随机抽奖，降低安全与合规复杂度。
- 所有奖励规则必须设置每日上限，避免重复点击、接口重放或刷分。
- 已购买商品永久进入用户库存；装备和卸下不重复扣分。

#### 数据设计

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| `points_accounts` | `user_id`, `balance`, `version` | 当前余额与乐观锁版本 |
| `points_transactions` | `user_id`, `amount`, `type`, `source_id`, `idempotency_key` | 不可变积分流水 |
| `store_items` | `name`, `category`, `price`, `status`, `asset_url` | 商城商品 |
| `purchases` | `user_id`, `item_id`, `price_paid`, `created_at` | 购买快照 |
| `user_assets` | `user_id`, `item_id`, `equipped` | 用户库存与装备状态 |

#### 关键接口

- `GET /api/v1/me/points`
- `GET /api/v1/me/points/transactions`
- `GET /api/v1/store/items`
- `POST /api/v1/store/purchases`
- `GET /api/v1/me/assets`
- `PUT /api/v1/me/assets/{item_id}/equip`

#### 验收标准

- 同一学习事件重复提交不会重复发放积分。
- 余额不足时购买失败且余额、库存均不变化。
- 扣积分和发放商品在同一数据库事务内完成。
- 每笔余额变化都能由流水还原并被管理员审计。
- 商城资源加载失败不影响已购权益记录。

### 4.3 错题本与间隔复习（P0）

#### 功能范围

- 记录题目来源、知识点、用户答案、正确答案、错误类型、尝试次数和时间。
- 支持单词、句型、听写、填空、发音和情景对话六类薄弱项。
- 相同知识点重复出错时合并为一个错题条目并累计证据，不制造重复卡片。
- 支持“今日复习”“按课程复习”“按知识点复习”和“只看高频错题”。
- 复习结果分为：未掌握、模糊、基本掌握、已掌握。
- 采用简单可解释的间隔策略，例如 1 天、3 天、7 天、14 天、30 天。
- 连续正确达到阈值后移出活跃错题，但保留历史记录并允许再次加入。
- 发音题保存分项评分，不默认长期保留原始儿童录音。

#### 数据设计

| 实体 | 关键字段 |
| --- | --- |
| `knowledge_points` | 类型、标准内容、课程来源、标签 |
| `wrong_items` | 用户、知识点、错误次数、掌握度、下次复习时间、状态 |
| `wrong_attempts` | 错题条目、答案、结果、评分、发生时间 |
| `review_sessions` | 开始时间、完成时间、题量、正确率、积分事件 |

#### 调度建议

- 首次错误：次日复习。
- 复习正确：间隔升级；复习错误：回到 1 天并降低掌握度。
- 连续 3 次正确且最近一次间隔达到 14 天，可标记“已掌握”。
- 每日题量默认 10–15 题，优先处理已到期和高频错误。

#### 验收标准

- 答错后 2 秒内可在错题本看到记录。
- 复习计划能跨设备同步，服务器时间决定是否到期。
- 完成一次复习后，掌握度、下次复习时间和积分在一个事务中更新。
- 历史已掌握条目仍可查询，后续再错时能自动恢复为活跃状态。

### 4.4 教材上传与内容生产流水线（P0）

#### 支持范围

- 首期支持结构化 JSON、Markdown、DOCX、PDF；图片扫描件进入 OCR 队列。
- 支持封面、插图和配套音频上传。
- 上传者选择年级、主题、难度、课程语言、版权来源和使用范围。
- 自动抽取单词、句子、中文释义和章节结构。
- AI 可辅助生成五类活动，但生成内容必须进入人工审核状态。
- 支持课程预览、逐题编辑、校验、审核、发布、下架和回滚。
- 发布后形成不可变课程版本；编辑产生新草稿，不直接改变学生正在学的版本。

#### 处理流程

| 阶段 | 状态 | 产物 |
| --- | --- | --- |
| 上传 | `uploaded` | 原文件、哈希、上传记录 |
| 解析 | `parsing` | 章节、文本、图片和错误报告 |
| 生成 | `generating` | 候选课程组件 |
| 校验 | `validation_failed` / `ready_for_review` | 契约、重复项、答案和资源检查 |
| 审核 | `approved` / `rejected` | 审核人和意见 |
| 发布 | `published` | 固定课程版本与资源清单 |

#### 必要校验

- 所有活动符合 `docs/lesson-components.md` 契约。
- 题目必须有唯一可判定答案或明确的宽松匹配规则。
- 音频文本、字幕和题目正文一致。
- 文件类型、大小、病毒扫描和对象存储路径合法。
- 上传者确认拥有教材数字化和分发权限。

#### 验收标准

- 一份标准教材能从上传走完整个“解析—预览—审核—发布”流程。
- 解析错误可定位到页码、章节或字段，不只返回笼统失败。
- 已发布版本可回滚，历史学习记录仍能引用原版本。
- 上传内容未经审核时学生端不可见。

### 4.5 教师后台与教学运营（P1）

#### 功能范围

- 班级、学生和邀请码管理。
- 课程分配、截止时间、补交规则和作业批次。
- 查看班级完成率、正确率、发音表现和薄弱知识点。
- 查看单个学生的学习轨迹与错题趋势。
- 对 AI 生成课程进行审核和发布。
- 管理积分奖励规则、商城商品上下架和违规积分修正。
- 导出必要的班级报表；导出行为进入审计日志。

#### 验收标准

- 教师只能查看自己有权限的班级。
- 作业修改不会破坏已提交记录。
- 统计口径有明确时间区间和数据更新时间。
- 人工积分调整必须填写原因并生成审计记录。

### 4.6 iOS 与苹果生态适配（P1）

#### 技术适配

- iPhone 小屏、刘海、灵动岛、安全区域和横竖屏策略。
- iPad 基础布局；首期可采用居中单栏，不强制多栏重做。
- 软键盘避让、输入焦点、返回手势和系统字体缩放。
- 麦克风权限、首次拒绝、永久拒绝和系统设置跳转提示。
- 音频录制与播放会话切换、静音键、耳机、蓝牙和来电中断恢复。
- 弱网、锁屏、切后台、进程被杀和恢复场景。
- 不同 iOS 版本上的 WebView/Expo DOM 兼容性。

#### 发布准备

- Apple Developer 账号、Bundle ID、证书和 Provisioning Profile。
- 应用图标、启动图、截图、年龄分级和商店文案。
- `Info.plist` 权限说明、Privacy Manifest 和第三方 SDK 隐私清单。
- 隐私政策、儿童使用说明、数据删除和账号注销入口。
- TestFlight 内测、崩溃收集、审核账号和审核说明。

#### 设备矩阵

- 至少覆盖一台小屏 iPhone、一台主流尺寸 iPhone、一台较新 iPhone 和一台 iPad。
- 至少覆盖当前主版本和前一个 iOS 主版本。
- 真机测试必须包括录音、TTS、耳机、弱网、后台恢复和权限拒绝。

#### 验收标准

- 核心学习流程在设备矩阵中无阻断。
- 首次安装后的权限路径清晰，拒绝权限仍能使用文本替代方案。
- TestFlight 构建可安装，崩溃和严重错误可定位到版本与设备。
- 满足 App Store 对未成年人数据、账号删除和隐私披露的要求。

### 4.7 作业与学习计划（P1）

- 教师布置课程、错题复习或专项训练。
- 支持开始时间、截止时间、预计时长和完成条件。
- 作业进度由真实活动结果计算，不由前端直接填写百分比。
- 支持迟交、重做和教师评语。
- 首页只展示可执行的近期任务，避免儿童信息过载。

### 4.8 学习成长与阶段评估（P1）

- 周/月学习时长、完成课程、掌握单词、复习正确率和发音趋势。
- 徽章与里程碑，例如连续学习、错题清零、主题课程完成。
- 每个单元增加入门诊断与结课测评。
- 区分“做过”“做对”和“稳定掌握”，避免仅用完成量表示学习效果。

### 4.9 家长端与通知（P2）

- 家长查看周报、学习时长、进步点和需要协助的知识点。
- 家长控制每日学习时长、可用时段、语音与 AI 权限。
- 通知包括作业临期、复习到期、连续学习提醒和周报。
- 默认控制频率，不用积分或连续签到制造过度焦虑。

### 4.10 离线与同步（P2）

- 缓存已发布课程、必要图片和高频音频。
- 离线产生的答题记录进入本地待同步队列。
- 服务端使用事件 ID 保证重试幂等。
- 积分购买等强一致操作必须在线完成。
- 内容版本变化时保留进行中的课程，下一次进入再提示更新。

### 4.11 AI 助教安全与质量（持续）

- 固定儿童友好的系统提示词、话题边界和回复长度。
- 对用户输入和模型输出进行敏感内容检测。
- 课程问答优先检索已审核教材，不允许模型伪造学习事实。
- 保存必要的质量与错误指标；默认不长期保存原始儿童语音。
- 为每个 AI 功能设置超时、重试、并发和每日成本上限。
- AI 失败时给出安全的模板回复，不伪装为真实模型结果。
- 建立人工抽检集：语言正确性、年龄适配、知识一致性和安全性。

## 5. 技术底座建设

### 5.1 数据库与迁移

- 从开发期 SQLite 过渡到生产 PostgreSQL。
- 引入 Alembic，所有表结构变更通过版本迁移完成。
- 为用户、课程版本、积分流水、错题到期时间和作业状态建立必要索引。
- 自动备份并定期演练恢复，不以“有备份文件”代替恢复验证。

### 5.2 文件与媒体

- 教材、图片和音频进入对象存储，不存数据库二进制字段。
- 使用带过期时间的签名 URL 控制上传和下载。
- 生成缩略图、媒体元数据和文件哈希，避免重复上传。
- 语音缓存增加生命周期和清理任务。

### 5.3 API 与任务系统

- API 统一分页、错误码、请求 ID 和时间格式。
- 上传解析、OCR、AI 生成和批量音频合成使用异步任务队列。
- 长任务提供状态查询、失败原因和安全重试。
- 写接口支持幂等键，特别是积分、购买、作业提交和同步事件。

### 5.4 阿里云 Token 自动刷新

- 不再把 24 小时临时 Token 当作长期配置。
- 服务端安全保存 RAM 用户的 AccessKey，授予最小 NLS 权限。
- 在 Token 过期前自动获取并刷新，应用进程只读取缓存后的有效 Token。
- AccessKey 不下发给前端、不写日志、不提交 Git。
- Token 获取失败进入告警，并自动回退系统语音。

### 5.5 可观测性

- 结构化日志：请求 ID、用户匿名 ID、接口、耗时、结果码和供应商错误码。
- 指标：API 成功率、P95 延迟、TTS/ASR 成功率、AI 成本和任务积压。
- 崩溃与前端异常按版本、设备和系统聚合。
- 告警区分阻断级、降级级和运营关注级。
- 严禁在日志中记录密码、AccessKey、Token、完整儿童录音和未经脱敏的对话。

### 5.6 自动化质量保障

- 后端：业务规则单测、API 集成测试、数据库迁移测试。
- 前端：状态逻辑单测、课程组件测试、关键页面交互测试。

## 8. 验收指标建议

### 学习效果

- 课程完成率。
- 错题进入复习后的 7 日掌握率。
- 同一知识点重复错误率变化。
- 发音评分提升趋势，不只统计单次高分。

### 产品体验

- 首次启动到开始第一课的成功率和耗时。
- 课程中途退出率与退出环节分布。
- TTS、ASR、评分和 AI 的成功率及降级率。
- 每周活跃学习天数和有效复习完成率。

### 技术质量

- 核心 API 可用性目标不低于 99.5%。
- 核心 API P95 延迟目标：普通数据接口低于 500ms；云语音和 AI 单独统计。
- 正式版崩溃自由会话目标不低于 99.5%。
- 积分账本对账差异为 0。
- 发布版本不存在阻断级缺陷或已知越权漏洞。

指标仅用于发现问题，不公开排名儿童，也不将学习时长简单等同于学习效果。

## 9. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 教材版权不清 | 无法合法发布 | 上传时记录来源与授权，发布前人工确认 |
| AI 生成错误或不适龄 | 教学与安全风险 | 审核流程、检索已审教材、输出过滤和抽检集 |
| 临时 Token 过期 | TTS/ASR 中断 | 服务端自动刷新、缓存与系统语音回退 |
| 积分并发或刷分 | 余额错误 | 幂等键、事务、唯一约束、每日上限和审计 |
| 错题数量持续膨胀 | 学生挫败 | 知识点合并、每日上限、掌握后归档 |
| iOS 审核被拒 | 发布时间延误 | 提前准备隐私、账号注销、权限文案和审核说明 |
| 第三方成本失控 | 运营不可持续 | 限额、缓存、供应商指标、预算告警和降级 |
| 本地与云端冲突 | 进度丢失或重复 | 事件 ID、服务端权威状态和明确冲突策略 |
